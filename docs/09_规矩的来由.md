# 09 规矩的来由

技能（`skills/`）里只写规矩本身。这里记每条规矩是用户在什么情况下说的，改技能时用来判断一条规矩还该不该留。agent 做板时不用读这个文件。

## 协作规矩

| 规矩 | 用户的原话 |
|---|---|
| 给选项，不问开放题 | 「我希望 agent 给我选项，而不是所有问题都我来想」 |
| 要用户选的东西先出图 | 「给我看图片，我再选」 |
| 卡住了说人话，明说要不要用户决定 | 「能不能告诉我到底遇到啥问题了」「需要我的决定吗」 |
| 低效要自己发现、自己提 | 「我还是建议优化一下布局，这轮跑的时间有点长了」 |
| 实验没效果记下结论，不重复试 | 「白跑的问题，别太在意，工具本来就不成熟」 |
| 目标比办法重要 | 「气球方法也只是我凭直觉想出来的，也许你能做得更好」 |
| 用户不该需要引导 agent | 「现在这个仓库用起来非常不舒服，居然还需要我用语言引导」 |
| 省 token，不反复回头看 | 「不能让 agent 每次都回头看一遍」 |

## 停点

| 停点 | 用户的原话 |
|---|---|
| S1 画原理图之前 | 「动手之前我们先核对一下需求」 |
| S2 摆件之前 | 「接下来先确认板框形状」 |
| S3 大件摆完 | 「先把上板的大元器件位置确定下来」；后来要求：做完大件布局必须先出图问意见，并留开关 |
| S4 布线之前 | 「在布线之前先根据飞线优化布局」 |
| S5 写进 EDA 之前 | 「给我看图片，我再选」 |
| S6 细节优化 | 「接下来我打算对细节进行优化（走线、过孔），先别动手，你有什么好办法吗」 |
| S7 换做法 | 「先别动手，帮我理清思路」「你可以暂停一下，我们重新思考一下」「先做可行性实验」 |
| S8 波及固件 | 「你需要现在就改引脚顺序吗」 |

## 板子的要求

| 要求 | 用户的原话或当时的情况 |
|---|---|
| 四个目标 | 「必须考虑板子测试的方便性，整体美观性，电气性能优良，鲁棒性好」 |
| 先做能单独测试的那块板 | 先做了下板，「导致下板的测试几乎无法进行」 |
| 操作件放板边、成组 | 「ec11 和五向开关得放在板边，方便操作……应该设计成方便联动操作的布局」 |
| 小阻容可放底面 | 「小的电容电阻允许放到板底面，不然太挤了」 |
| 低速板线成束、扩大铺铜 | 「不应该追求更短的走线……应该扩大铺铜区，使信号线等距聚拢」 |
| 过孔要少 | 「现在的过孔太多了，应该想办法降一降」 |
| 不给碎铜打孔凑数 | 「你就打两个过孔，把假铺铜接到地上，这能有什么用啊」 |
| 电源层分区、信号不穿电源铺铜、电感禁布、散热孔设地、全 45° | 2026-11-08 否决第一版下板布线时逐条提出 |
| 不用加权搜索 | 「我不推荐加权搜索，听起来没什么意义」 |
