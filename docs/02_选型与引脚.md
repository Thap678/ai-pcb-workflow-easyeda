# 02 选型与引脚分配

## 选型：每个器件落到一个能买、能贴的 LCSC 料号

```bash
easyeda lib search --query "TPS54560"            # 按型号 / 值+封装 / 名称搜库
easyeda lib by-lcsc --lcsc C123456,C789012       # LCSC 编号 -> 库里的器件（libraryUuid + uuid）
```

- 原理图规格里每个元件写 `lcsc`（推荐）或 `lib` + `uuid`（库里没有 LCSC 编号的器件，例如个人库/系统库的模块封装）。
  **`uuid` 必须是器件（device）UUID，不是符号 UUID**：`lib search` 结果里的 `uuid` 才是器件；用符号 UUID 放置会一直超时。
- 选型时同时看：库存和是否是嘉立创「基础库」（贴片费低）、封装是否适合手焊/机贴、**焊盘尺寸和间距**。
- 解析结果会缓存到 `kit/sch/lcsc_cache.json`，之后离线也能用。

## 引脚分配：写成代码，让脚本检查

MCU 的引脚表是整块板最容易出错、错了代价最大的地方。不要在表格里手填，写成代码（模板 [templates/pinmap_template.py](../templates/pinmap_template.py)），每次修改都自动检查：

- 0 重复引脚；每个信号用的引脚确实有这个外设功能（对照芯片手册/官方引脚图的 AF 表）；
- 外部中断（STM32 的 EXTI 线号 = 引脚号）不冲突，冲突的要么换脚，要么在固件里改成轮询；
- 板载占用的脚（下载口、板载 LED/Flash/按键）不分配；
- 核心板插座的脚位映射（插座第几针 = 哪个 GPIO）和实物一致——用核心板的**底面视图**核对。

引脚表同时生成：给人看的 Markdown 表、给固件用的头文件（示例生成 `qh_core_pinmap.h`）、给原理图规格用的 JSON。三者同源，不会互相对不上。

## 进阶：用飞线交叉数优化引脚和接口分配

示例里用 `examples/nuedc-car-2026/inputs/swapopt.py` 做了一次「换脚优化」：在保证每个信号的外设功能不变的前提下，交换可互换的引脚（同一定时器的通道、同组 GPIO、叠板连接器的槽位、串口座的去向），用模拟退火把**飞线交叉数**从 871 降到 371。结果：同一块板布线后过孔从 431 降到 251。

做法要点：

- 先列出「可交换组」和约束（哪些脚必须固定、EXTI 不能重复、某个脚要留给另一块板）；
- 目标函数 = 交叉数 + 0.1 × 飞线总长（mm）；多个随机种子跑，取最好且合法的；
- 结果要经过审计（逐个信号核对外设功能），通过后再改引脚表、重新生成原理图规格。

这一步对密度高、飞线乱的板子收益很大；简单板子可以跳过。

## 过关标准

- 引脚表自检全过；
- 关键器件（MCU/核心板、电源芯片、驱动芯片、连接器）用户确认过；
- 所有元件都有 `lcsc` 或 `lib`+`uuid`。
