# AI 画板：总流程

目标：用户只说一句「做板子」或「继续」，你就能自己把事情往下推，只在**需要用户拍板**和**交付阶段成果**时开口。
这套技能里的规矩不是设想出来的，是一位用户带着 agent 做完两块板（2 层主控板、4 层驱动电源板）期间反复纠正出来的。照着做，用户就不用再说一遍。

## 路径

- 仓库根目录 `ROOT` = 本文件所在目录的上两级（Claude Code 里是 `${CLAUDE_SKILL_DIR}/../..`）。
- 脚本在 `ROOT/kit/`，方法说明在 `ROOT/docs/`，模板在 `ROOT/templates/`，完整示例在 `ROOT/examples/nuedc-car-2026/`。
- 下文命令里的 `kit/...`、`docs/...` 都相对 `ROOT`。脚本在**用户的项目目录**里运行（那里放 `board.toml`），所以实际命令是 `python <ROOT>/kit/...`。

## 开工（每次会话都做，不用问用户）

1. `pip install -r <ROOT>/requirements.txt`（第一次），然后 `python <ROOT>/tools/check_env.py`。有 FAIL 就按 `docs/00_准备环境.md` 修；只有「EDA 没开 / 工程没打开」这类你做不了的事才请用户动手。
2. 项目目录里没有 `board.toml`：从 `ROOT/board.example.toml` 复制一份，用 `easyeda doc ls --project <工程名>`、`easyeda health` 和工程的 `.eprj3` 自己填 UUID、尺寸、孔位。填不出的（板子尺寸、孔位）留到阶段 1 问。
3. 找交接文档（项目目录里的 `*交接*.md`，或需求文档末尾的「决策记录」）。有就先读完：里面是用户已经拍过板的事，**不要再问一遍，也不要推翻**。
4. 判断阶段（下表），用一句话告诉用户「现在在第 N 阶段，下一步做什么」，然后直接做。

## 判断项目在哪个阶段

| 看到什么 | 阶段 | 用哪个技能 |
|---|---|---|
| 没有需求文档，或文档里还有待定项 | 1 需求与方案 | pcb-requirements |
| 需求已确认，没有引脚表 / 元件没有料号 | 2 选型与引脚 | pcb-requirements |
| 没有页面规格 JSON，或 `build_pages.py` 的核对不是 0 problems | 3 原理图 | pcb-schematic |
| PCB 上没有元件，或元件堆在板外、没有锁定 | 4 布局 | pcb-placement |
| 元件已摆好，没有走线，或走线被否决 | 5 布线与铺铜 | pcb-routing |
| DRC 和连通检查都过了 | 6 出板 | pcb-release |

拿不准就读现状：`python <ROOT>/kit/dump.py now.json`（元件、走线、过孔、铺铜各多少）、`easyeda --project <P> --doc <页> sch list`。
多块板时逐块判断。**先做能单独上电测试的那块**（通常是主控板），另一块的板框、孔位、叠板连接器位置同时定下来。

## 硬规则

1. **读回为准，不信回执。** easyeda 连接器会假失败（写进去了却报失败）和假成功（报成功却没写进去）。每次写操作后用读命令确认，再决定重试还是继续。创建类命令（导线、过孔、铺铜、导入）只发一次。
2. **大改前先备份，备份放工作区外。** `python <ROOT>/kit/backup.py <标签>`。重新导入、重新布线、改规则、批量改原理图之前都要做。
3. **永远不下单、不发布。** 不调用 `placePcbOrder` 等下单接口。下单、付款、公开发布、推送用户的仓库，只能用户本人做。
4. **不覆盖用户的手工修改。** 用户会在 EDA 里自己换封装、挪元件、改测试点。每次动手前先 dump，和上次的快照比；用户改过的地方以 EDA 为准，并回写进规格文件和坐标表。用户说「我改过 X」，先读回 X 再继续。
5. **每阶段过关才进下一阶段。** 过关标准在各阶段技能里。没过关就停下来修，或把问题和选项交给用户。
6. **长任务放后台，并行跑。** 布线一版 15–45 分钟且是单线程：几组参数各占一个核同时跑。不要前台卡住，不要轮询刷屏。等的时候可以回答用户的问题。
7. **原地改板的 CLI 命令要经过守护脚本**（`pcb auto-place` / `route-short` / `beautify` → `kit/pcb/guard.py`）。它们失败时不回滚。
8. **写完 EDA 后先 `doc reload` 再查。** 批量写入后连通缓存是旧的，DRC 会虚报几百条断线；铺铜要逐个网络重铺。
9. **记录决策。** 用户拍板的方案、参数、例外、否决过的办法，当场写进交接文档。

## 和用户协作的规矩

每条后面的引号是用户当时的原话。

1. **给选项，不问开放题。** 2–3 个现成选项，标出推荐项和代价（时间、成本、风险）。用户说「按推荐定」就照推荐走。——「我希望 agent 给我选项，而不是所有问题都我来想」
2. **只有用户知道的事，一次问清。** 机械尺寸、操作习惯、哪些接口必须引出、手上有什么模块。问的时候也尽量给选项。
3. **要用户选的东西，先出图。** 布局、布线方案、铺铜效果都渲染成图再问。——「给我看图片，我再选」
4. **用户说「先别动手」「你有什么好办法」时，只出思路和选项**，不改板子。说完等用户选。用户常在哪些位置这样说，见下面的「停点」表；到了那些位置不用等用户说。
5. **卡住了就说人话。** 讲清卡在哪个件、哪根线、为什么；并且明说「需要你决定」还是「不需要，我继续」。不要只报第几轮、剩几条。——「能不能告诉我到底遇到啥问题了」「需要我的决定吗」
6. **低效要自己发现、自己提。** 布线一轮超过 40 分钟还没收敛，或同一处反复失败，就停下来看位置、提改布局的选项，不要等用户来说。——「我还是建议优化一下布局，这轮跑的时间有点长了」
7. **会波及别处的改动先问。** 对调引脚、把芯片换到底面、改接口针序，都会影响固件、贴片费或另一块板。问的时候说清影响；同意后把「固件要跟着改什么」写进交接文档和出板说明。
8. **用户否决的办法记下来，不再提。** 实验没效果也一样：把结论写进交接文档，不重复试，也不用反复道歉。——「白跑的问题，别太在意，工具本来就不成熟」
9. **结果先说结论。** 用户问「做得怎么样了」，第一句是状态（布通没有、还差什么），细节在后面。
10. **用户的直觉要认真对待，但目标比办法重要。** 用户提的办法没达到目标时，说明原因并给出能达到同一目标的替代办法。——「气球方法也只是我凭直觉想出来的，也许你能做得更好」

## 停点：到这里必须停下来，出思路、出图、给选项

用户在下面这些位置都说过「先别动手」或类似的话。到了这些位置，**不要接着往下做**：把要交的东西交出来，问用户意见，等回答。

| 编号 | 停在哪 | 交什么 | 用户当时的话 | 开关 |
|---|---|---|---|---|
| S1 | 需求写完，画原理图之前 | 需求文档 + 待定项选择题，逐条核对 | 「动手之前我们先核对一下需求」 | 开 |
| S2 | 导入 PCB 之后，摆件之前 | 板框图和尺寸、安装孔位置，2–3 个板框方案 | 「接下来先确认板框形状」 | 开 |
| S3 | **大件摆完，摆小件之前** | 大件布局图，问用户意见（接口朝向、操作件位置、模块方向） | 「先把上板的大元器件位置确定下来」 | 开 |
| S4 | 布局摆完，布线之前 | 飞线优化前后的数字和图，打算走哪条布线路线 | 「在布线之前先根据飞线优化布局」 | 开 |
| S5 | 布通之后，写进 EDA 之前 | 候选版本的成品图并排，每版一句话差别 | 「给我看图片，我再选」 | 开 |
| S6 | 布通之后想做细节优化（走线、过孔、铺铜）时 | 只出办法和各自的代价，不改板子 | 「我打算对细节进行优化，先别动手，你有什么好办法吗」 | 开 |
| S7 | 要换一种做法、要写新算法、或者同一办法两轮没有改善时 | 停下来说明现状，给 2–3 个方向；新办法先做一个小的可行性实验再铺开 | 「先别动手，帮我理清思路」「你可以暂停一下，我们重新思考一下」「先做可行性实验」 | 开 |
| S8 | 改动会波及固件、贴片费或另一块板（对调引脚、换面、改针序） | 影响说明 + 选项 | 「你需要现在就改引脚顺序吗」 | 常开 |
| S9 | 出板文件导出之后 | 检查报告、成品图、出板说明；下单由用户做 | — | 常开 |

**开关怎么用：** 把上表「开关」一列的「开」改成「关」，这个停点就不再停。项目的交接文档里如果有同名的「停点开关」表，以交接文档为准（新建交接文档时把这张表抄进去，用户改那一份就只影响这个项目）。
关掉的停点：不停、不问，按推荐项往下做；但图照样生成并存到项目目录，选了什么、为什么，记进交接文档。S8、S9 不能关。

用户在别的位置说了「先别动手」：照做，并把这个位置补进交接文档的停点表，下次到这里也停。

## 一块好板子的四个目标

每个阶段都对照这四条；布局、布线、出板的过关标准里各有一条「四个目标对照过」。给用户选项时，说明每个选项对这四条的影响。

1. **好测试。**
   - 每路电源、关键信号（总线、使能、复位、电机驱动输入）有测试点，旁边有地的夹持点；测试点和调试口不被模块、屏幕、叠板挡住。
   - 调试口（SWD、串口）在板边，装进整机后也够得着。
   - 每块板能单独上电测试；各路电源之间留跳线或 0 Ω，出问题能逐路断开排查；每路电源一个指示灯。
   - 丝印标清：测试点名字、接口功能和 1 脚、电源极性、版本号和日期。
2. **好看。**
   - 元件对齐、同类同向、间距均匀；接口沿板边排齐。
   - 线成束、等距、全 45°；铺铜大块连续，没有碎铜和孤线。
   - 丝印方向统一、不压焊盘、不被元件盖住。
3. **电气性能好。**
   - 去耦电容贴着电源脚；开关电源的回路小，电感下方禁布；模拟和采样远离开关节点和电机线。
   - 信号下面有完整的地做回流；电源按电流给够线宽、铺铜和过孔数。
   - 电源层按电源分区，信号线不穿过电源铺铜块。
4. **皮实（鲁棒）。**
   - 输入有防反接、保险、TVS；对外接口有 ESD 或限流；接口防呆，插不反、插不错位。
   - 复位、启动模式、使能、驱动输入有上下拉：主控没上电或在复位时，电机不会乱转。
   - 器件留余量（电压、电流、温度）；发热件有散热铜和地孔。
   - 安装孔周围留禁布；板边不放易碰的件；能手焊返修。

## 交接文档

项目目录里放一份 `<项目名>_交接.md`（没有就建）。每次会话结束前更新：

- 现在在哪个阶段，过了哪些关，下一步是什么；
- 用户的每个决定：日期、选了什么、理由、影响；
- 否决过的办法和原因；
- 「停点开关」表（从上面抄过来，用户可以逐项改成「关」）；
- 固件要跟着改的地方；
- 备份放在哪，关键快照的文件名。

下一个 agent（或下一次会话）先读它，用户就不用重复交代。

## 出问题时

- 症状查 `docs/07_踩坑清单.md`，大部分都在里面。
- 工作区丢了：`docs/08_备份与恢复.md`。
- 环境、版本：`docs/00_准备环境.md`。
